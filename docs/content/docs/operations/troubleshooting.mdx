---
title: "Troubleshooting"
description: "Find the cause of a problem and collect the information needed for help."
---

Start with the error shown in Citadel's operation panel or **Activities** page.
Wait for the current operation to finish before trying it again.

## Citadel will not open

From your installation directory, run:

```bash
docker compose ps
docker compose logs --tail=100 server pg_db
```

- For the supplied local setup, use **http://localhost:18000**, not port `8000`.
- Open that address on the machine running Citadel. For another machine, use your configured HTTPS address.
- If PostgreSQL cannot start, check `PG_PASSWORD` and persistent storage. Changing its initial password in `.env` does not reset an existing database password.
- If an image download fails, check the image address, version, and registry access in `.env`.

## A Platform stays offline

Check Docker is running on the target host. For a regular Agent, check its
container and whether Core can reach its Agent address. For an Edge Agent,
check enrollment and whether it can reach Core's **gRPC** address. Follow
[Agent troubleshooting](/docs/operations/agent#troubleshooting) or
[Edge Agent troubleshooting](/docs/operations/edge-agent#troubleshooting).

For Swarm, check manager health and node-agent coverage. Adding another Platform
record for the same Docker engine will not repair connectivity.

## Live updates stop

The header reports the browser's connection to Citadel Core:

| Status | Meaning and next step |
| --- | --- |
| **Live updates interrupted** | Citadel is reconnecting. Wait for recovery; displayed information may be outdated. |
| **Live updates unavailable** | Automatic recovery has stopped. Select the header's retry indicator after checking that Core is reachable. |
| **You're offline** | Restore the browser's network connection. |

This connection is separate from a Platform's Agent connection. An interruption
does not by itself mean that Docker workloads stopped. Once connected, check the
workload and its operation history before repeating a command.

If the problem persists behind a reverse proxy, check WebSocket upgrades and
long-lived connection timeouts. See [TLS and secure Agent transport](/docs/operations/tls-and-secure-agent-transport)
or the [Caddy example](/docs/operations/reverse-proxy-caddy).

## An action is unavailable

Check the disabled action's explanation, then review:

- **Access:** your Role and any resource-specific permissions. Seeing a resource
  does not grant permission for every action; see [access control](/docs/guides/access-control).
- **State:** wait for an operation in progress, restore the Platform connection,
  or refresh stale container information.
- **Ownership:** manage Swarm Tasks through their Service or Stack. Citadel's
  own system containers are protected from ordinary lifecycle actions.
- **Selection:** inspect one resource at a time; group actions require eligible
  targets. Networks and volumes in use cannot be deleted from their lists.

For an option marked as license-restricted, check
[feature availability](/docs/overview/licensing). A license change does not
replace the user's permissions or the action's runtime requirements.

## A resource or account is missing

Clear list filters and try [global search](/docs/guides/finding-resources).
Search only returns resources your account can read. Ask an administrator to
review your Roles, enabled Team memberships, and direct grants if expected access
is missing. An empty **Updates available** list only means no detected updates
match the current filters.

For sign-in problems, check the account's enabled state, use an MFA recovery
code when applicable, or follow [OIDC troubleshooting](/docs/guides/oidc-providers#troubleshooting).
Another administrator can help recover a local account. Restarting Core does
not reopen setup; do not delete installation data to reset a password.

## A container terminal will not connect

The container must be running and your account must have terminal access. Choose
**sh** if the image does not include **bash**; some minimal images have no shell.
For a Swarm Task on another Node, verify
[node coverage](/docs/resources/platforms/docker-swarm#understand-cluster-node-coverage).
If logs and statistics also stop updating, check the browser connection above.

See [container tools](/docs/resources/docker/containers) for the normal workflow
and [volume troubleshooting](/docs/resources/docker/volumes#if-browsing-fails)
for file access problems.

## An application will not deploy

Read the failed operation's error. Check the image name and registry access,
whether the host port is already used, and whether the requested volumes exist.
For a Stack, fix editor or preflight errors before selecting **Deploy**.
Saving configuration alone does not deploy it.

## The application is running but its page will not open

Use the Docker host's address and the **published host port**, not the container
port. Check the application's logs, port mapping, and host firewall. A running
container does not always mean the application inside it is ready.

## Configuration changed but the application did not

Saving a Stack, Deployment, or binding changes Citadel's desired configuration.
Deploy or apply the consuming resource to change its runtime. Check which image,
commit, and release actually ran; [update checks](/docs/guides/application-updates)
detect changes without applying them.

For unresolved or stale secret values, use
[binding troubleshooting](/docs/guides/variables-and-secrets#troubleshooting).
For image pulls or Build pushes, use
[registry troubleshooting](/docs/resources/registries#troubleshooting).

## An alert arrives, or an expected notification is missing

Open **Alerts** and inspect the event's resource, time, and **Info**. Check the
resource's current state before acting on an older notification. Acknowledge
while investigating and resolve after verifying recovery; neither action
changes the workload. See [responding to an alert](/docs/resources/alert-rules#respond-to-an-alert).

If no message arrives, first check whether Citadel created an event. No event
points to rule evaluation, scope, or unavailable observations. An event without
a message points to channel assignment or delivery. Follow
[alert troubleshooting](/docs/resources/alert-rules#troubleshooting) for each case.

## Get help

Report reproducible defects in [GitHub Issues](https://github.com/Citadel-P/Citadel/issues).
Include the Citadel version, Platform and connector type, what you expected,
what happened, the time of the failed operation, and the relevant error text.

Remove passwords, tokens, secret values, and personal data from logs and
screenshots. Do not attach `.env`, private keys, or a database dump.
