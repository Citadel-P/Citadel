---
title: "Upgrade and rollback"
description: "Update Citadel while keeping a way to recover your accounts and settings."
---

These steps are for an installation using a published image. For a source build,
review the changes on `main`, back up first, update the checkout, and rebuild
with `docker compose up -d --build` from `deploy`.

## Before an upgrade

1. Read the target [release notes](https://github.com/Citadel-P/Citadel/releases).
2. Back up PostgreSQL and `citadel_data` together. Check that you can retrieve the backup.
3. Record the current complete Core and Agent image addresses, including their versions or digests.
4. Confirm the current installation is healthy.

## Upgrade

Open your existing `.env`. Change **`CITADEL_IMAGE`** to the complete published
image address for the chosen version, for example
`ghcr.io/citadel-p/citadel:VERSION` with `VERSION` replaced. Changing only
`CITADEL_IMAGE_TAG` does not override an active `CITADEL_IMAGE` value.

From the installation's `deploy` directory, run:

```bash
docker compose pull
docker compose up -d --no-build
docker compose ps
```

Include your TLS overlay in these commands if you use it. Citadel updates its
database during startup. Check sign-in, Platform connectivity, and a normal
application operation before removing the old backup. Update Agents using the
new generated setup command when the release notes require it.

## Rollback

Changing the image back does **not** undo database changes. Use an earlier image
without restoring data only when the release notes confirm it is compatible.
Otherwise stop Core and restore the matched pre-upgrade PostgreSQL and
`citadel_data` backup before starting the previous image. Follow
[control-plane recovery](/docs/operations/control-plane-recovery).

Use exact patch versions or digests for repeatable installations. Citadel's
release workflows publish patch, minor, and major aliases, but no `latest` tag.
