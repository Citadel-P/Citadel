---
title: "Install and secure Citadel"
description: "Choose an installation, protect network access, and preserve your data."
---

For a first local trial, use the [quick start](/docs/getting-started/quick-start).
For a shared installation, the person responsible for your Docker server should
complete the steps below before creating user accounts.

## 1. Choose the code or image

Check the [release notes](https://github.com/Citadel-P/Citadel/releases) for an
available version, its image address, and upgrade instructions. The version in
`version.json` alone does not mean an image has been published.

If no release image is available, use the source build in the quick start.
For a release, clone its exact tag (replace `VERSION` with the version you chose):

```bash
git clone --branch vVERSION --single-branch https://github.com/Citadel-P/Citadel.git
cd Citadel/deploy
cp .env.example .env
chmod 600 .env
```

Open `.env`, set a unique `PG_PASSWORD`, and replace the local image setting
with the **complete published image address**, including the exact version:

```text
CITADEL_IMAGE=ghcr.io/citadel-p/citadel:VERSION
```

Replace `VERSION` before running any commands. Setting `CITADEL_IMAGE_TAG` alone
will not select a published image while `CITADEL_IMAGE=citadel-rust:local` is set.
Citadel's release workflows do not publish `latest`.

## 2. Protect network access

The supplied `.env.example` uses local HTTP. Its default browser address is
`http://localhost:18000`; both published ports bind to `127.0.0.1`.

For a shared installation, choose one of these options:

| Option | Who should use it? | What to configure |
| --- | --- | --- |
| Reverse proxy | You already have a proxy that manages HTTPS certificates | `Transport__Mode=ReverseProxy`, public URLs, trusted proxy addresses, and an HTTP/2 gRPC route if you use Edge Agents |
| Direct TLS | Citadel will serve HTTPS itself | `Transport__Mode=Direct`, public URLs, certificates, and `compose.direct-tls.yml` |

Follow [TLS and secure Agent transport](/docs/operations/tls-and-secure-agent-transport)
for the full settings. Do not simply change the bind address to `0.0.0.0`
while leaving local HTTP enabled. Set `Transport__PublicUrl` to the browser
address users will actually open. If you use Edge Agents, also set
`EdgeAgent__PublicGrpcUrl` to the separate address those Agents can reach.

## 3. Start and check

For a published image, from the `deploy` directory:

```bash
docker compose pull
docker compose up -d --no-build
docker compose ps
```

For direct TLS, include the supplied overlay in each Compose command:

```bash
docker compose -f docker-compose.yml -f compose.direct-tls.yml up -d --no-build
```

The overlay mounts the certificate directory; the base Compose file controls
host bindings and ports. Confirm both services are healthy, open your configured
browser address, and complete [first-run setup](/docs/getting-started/first-run-setup).

## 4. Protect your installation data

Keep `.env` private. Keep the `citadel_data` and `postgres_data` volumes: together
they hold accounts, settings, history, and the keys used to protect saved secrets.
Configure a [control-plane backup](/docs/guides/backups) and keep a copy away
from the Docker host. Do not delete these volumes during an upgrade.

See [requirements](/docs/getting-started/requirements),
[configuration](/docs/getting-started/configuration), and
[upgrade and rollback](/docs/operations/upgrade-and-rollback) when planning a
permanent installation.
