---
title: "Install and secure Citadel"
description: "Install published Citadel images with Docker Compose and configure secure access."
---

Install Citadel and PostgreSQL with Docker Compose. You need a Linux Docker
host, Docker Compose **2.30 or newer**, curl, and a text editor.
The installation uses published container images.

## 1. Download the installation files

For a new installation, create a directory and download the Compose file and
environment template:

```bash
mkdir -p citadel
cd citadel
curl -fSL https://raw.githubusercontent.com/Citadel-P/Citadel/main/deploy/install/docker-compose.yml -o docker-compose.yml
curl -fSL https://raw.githubusercontent.com/Citadel-P/Citadel/main/deploy/install/.env.example -o .env
chmod 600 .env
```

Keep both files in this directory. For an existing installation, follow
[upgrade and rollback](/operations/upgrade-and-rollback) and keep your
existing `.env` and Compose project name.

If the download returns `404` because repository access is restricted, open
[the installation folder](https://github.com/Citadel-P/Citadel/tree/main/deploy/install)
while signed in to GitHub. Download `docker-compose.yml` and `.env.example`,
save them in your installation directory, rename `.env.example` to `.env`,
and run `chmod 600 .env`.

## 2. Configure Citadel

Open `.env` in a text editor and set **`PG_PASSWORD`** to a long, unique
password containing letters and numbers, without surrounding quotes.
You can generate one with `openssl rand -hex 32`. This is the only required
setting and is separate from your Citadel sign-in password.

If port `18000` is already in use, uncomment `CITADEL_HTTP_PORT` and choose
another port. The local browser URL follows that port automatically.

Compose uses `ghcr.io/citadel-p/citadel:latest` by default. To pin a version,
add `CITADEL_IMAGE` with the complete image address from your chosen
[release](https://github.com/Citadel-P/Citadel/releases).

The selected image must be published and accessible to your Docker host.
Restricted packages require registry access; a tag that has not been published
cannot be pulled. If a download fails, check the image address and access before
retrying, or use the [source-development setup](https://github.com/Citadel-P/Citadel/blob/main/docs/DEVELOPMENT.md)
to build from a checkout.

### Network access

The supplied `.env` uses local HTTP. Its default browser address is
`http://localhost:18000`; only the browser/API port is published, bound to `127.0.0.1`.
Edge Agent host access is optional; see [Edge Agent access](/getting-started/configuration#edge-agent-access).

For a shared installation, choose one of these options:

| Option | Who should use it? | What to configure |
| --- | --- | --- |
| Reverse proxy | You already have a proxy that manages HTTPS certificates | `CITADEL_TRANSPORT_MODE=ReverseProxy`, public URLs, trusted proxy addresses, and an HTTP/2 gRPC route if you use Edge Agents |
| Direct TLS | Citadel will serve HTTPS itself | `CITADEL_TRANSPORT_MODE=Direct`, public URLs, certificates, and `compose.direct-tls.yml` |

Follow [TLS and secure Agent transport](/operations/tls-and-secure-agent-transport)
for the full settings. Do not simply change the bind address to `0.0.0.0`
while leaving local HTTP enabled. Set `CITADEL_PUBLIC_URL` to the browser
address users will actually open. Whenever Core uses HTTPS—through a reverse
proxy or with its own certificate—it also requires an HTTPS
`CITADEL_EDGE_PUBLIC_GRPC_URL`, even when you do not use Edge Agents.
In that case, set it to the same HTTPS URL as `CITADEL_PUBLIC_URL`; no Edge port
publication or gRPC proxy route is needed. Before connecting Edge Agents,
configure it to the reachable gRPC endpoint and enable the corresponding route
or port publication.

For a complete reverse-proxy setup using the same Compose installation, follow
[Reverse proxy with Caddy](/operations/reverse-proxy-caddy).

## 3. Start and check

For local HTTP, run from your `citadel`
installation directory:

```bash
docker compose pull
docker compose up -d
docker compose ps
```

For direct TLS, download the overlay described in the
[TLS guide](/operations/tls-and-secure-agent-transport#direct-core-tls)
and use these commands instead:

```bash
docker compose -f docker-compose.yml -f compose.direct-tls.yml pull
docker compose -f docker-compose.yml -f compose.direct-tls.yml up -d
docker compose -f docker-compose.yml -f compose.direct-tls.yml ps
```

The overlay mounts the certificate directory; the base Compose file controls
the browser host binding and port. For Edge Agents, also include the Edge
overlay as shown in the TLS guide. Include your overlays in later Compose commands too.
For a reverse proxy, use the Compose commands in your chosen proxy guide.

Wait until `server` and `pg_db` are healthy. For the default local setup, open
[http://localhost:18000](http://localhost:18000) on the Docker host and create
your administrator account. There are no default credentials. If you installed
on a remote server, use the HTTPS address you configured above.

Complete [first-run setup](/getting-started/first-run-setup),
then [connect your first Platform](/getting-started/first-platform).

## 4. Protect your installation data

Keep `.env` private. Keep the `citadel_data` and `postgres_data` volumes: together
they hold accounts, settings, history, and the keys used to protect saved secrets.
Configure a [control-plane backup](/resources/backups) and keep a copy away
from the Docker host. Do not delete these volumes during an upgrade.

See [requirements](/getting-started/requirements),
[configuration](/getting-started/configuration), and
[upgrade and rollback](/operations/upgrade-and-rollback) when planning a
permanent installation.
