title: "Environment variables"
description: "Reference the production settings exposed by Citadel's Docker Compose environment template."
---

Citadel runtime settings use `CITADEL_` followed by uppercase words separated
by single underscores. Standard tool settings such as `RUST_LOG`, `DOCKER_HOST`
and `PG_*` retain their names. The `.env` downloaded in the [installation guide](/docs/getting-started/install)
contains the settings needed to start Citadel. Add optional settings from this
reference as needed. The defaults are for local HTTP; configure TLS before
sharing an installation.

## Installation and transport

| Setting | Required when | Purpose |
| --- | --- | --- |
| `CITADEL_IMAGE` | Optional | Blank or unset uses `ghcr.io/citadel-p/citadel:latest`; set a complete image address to override |
| `CITADEL_BIND_ADDRESS` | Optional | Host bind address; defaults to `127.0.0.1` |
| `CITADEL_HTTP_PORT`, `CITADEL_EDGE_PORT` | Optional | Host ports; default to `18000` and `18001` |
| `PG_HOST` | External or renamed PostgreSQL | PostgreSQL hostname; Compose defaults to `pg_db` |
| `PG_USER`, `PG_PASSWORD`, `PG_DATABASE` | Always | PostgreSQL credentials and database |
| `CITADEL_TRANSPORT_MODE` | Always | `ReverseProxy`, `Direct`, or development-only `Disabled` |
| `CITADEL_PUBLIC_URL` | Always | Canonical browser and API origin |
| `CITADEL_EDGE_PUBLIC_GRPC_URL` | Edge Agent use | Public Edge gRPC address |
| `CITADEL_HTTP_ALLOWED_HOSTS` | Always | Semicolon-separated hostnames accepted by Core |
| `CITADEL_HTTP_TRUSTED_PROXIES` | Reverse proxy | Immediate trusted proxy address |
| `CITADEL_HTTP_TRUSTED_PROXY_NETWORKS` | Reverse proxy alternative | Immediate trusted proxy network |
| `CITADEL_TLS_CERTIFICATE_PATH` | Direct TLS | PEM certificate chain inside Core |
| `CITADEL_TLS_PRIVATE_KEY_PATH` | Direct TLS | PEM private key inside Core |
| `CITADEL_JWT_ISSUER`, `CITADEL_JWT_AUDIENCE` | Optional override | Token validation identities; otherwise derived from the public URL |
| `CITADEL_JWT_KEY` | Optional | Explicit signing key; otherwise persisted in `citadel_data` |
| `CITADEL_SECRETS_ENCRYPTION_KEY` | Optional | Explicit 32-byte base64 key; otherwise persisted in `citadel_data` |
| `CITADEL_MFA_POLICY` | Optional | `Optional`, `RequiredForAdministrators`, or `RequiredForAllUsers` |
| `CITADEL_PASSWORDS_MINIMUM_LENGTH` | Optional | Minimum password length, default 15; accepts 8–128, with a fixed maximum password length of 128 |
| `CITADEL_HTTP_OPENAPI_ENABLED` | Optional | Exposes Swagger and the full/public OpenAPI documents; false by default |

`CITADEL_IMAGE`, `COMPOSE_PROJECT_NAME`, and host port settings control Compose.
The application settings must reach the Core container; the supplied Compose
file reads `.env` for this purpose. Recreate Core after editing it:

```bash
docker compose up -d server
```

Keep the installation's project and overlay options on that command. A container
restart alone does not load a changed Compose environment.

## Update checks

| Setting | Default | Purpose |
| --- | --- | --- |
| `CITADEL_UPDATE_CHECKS_ENABLED` | `true` | Allow Core to check public releases in its installed channel at startup and every six hours; no automatic installation |

No Citadel telemetry or instance data is sent. GitHub receives normal connection
information, including the outbound IP address. See
[update checks and privacy](/docs/getting-started/configuration#allow-update-checks)
for details and how to turn checks on or off.

## Database and persistent paths

Core chooses its database connection in this order:

1. `CITADEL_DATABASE_URL`, if set: a PostgreSQL URI (`postgres://` or `postgresql://`). A blank or malformed selected URI fails startup.
2. Otherwise, `PG_HOST`, `PG_PORT`, `PG_USER`, `PG_PASSWORD`, and `PG_DATABASE`; credentials are escaped when constructing the URI.

Remove unused overrides instead of leaving them blank. The supplied Compose
PostgreSQL service still requires its `PG_*` credentials. Changing the initial
database password in `.env` does not reset the password of an existing database.

| Setting | Default | Purpose |
| --- | --- | --- |
| `PG_PORT` | `5432` | PostgreSQL port used with the `PG_*` connection settings |
| `CITADEL_DATA_ROOT` | `/app/data` | Persistent Core data and generated recovery keys; match the container's data mount |
| `CITADEL_HOST_ROOT` | `/host` | Read-only host mount used for Docker storage filesystem metrics |
| `CITADEL_PG_DUMP_PATH` | `pg_dump` | PostgreSQL dump executable for control-plane backups |
| `CITADEL_PG_RESTORE_PATH` | `pg_restore` | PostgreSQL restore executable used by offline `restore-system` |

Preserve original keys and verify the database target before
[control-plane recovery](/docs/operations/control-plane-recovery). A new Compose
project does not isolate an external database configured by an override.

## Jobs and diagnostics

| Setting | Default | Purpose |
| --- | --- | --- |
| `CITADEL_STATS_POLL_INTERVAL_SECONDS` | `10` | Platform metric collection interval, in seconds |
| `CITADEL_STATS_FLUSH_INTERVAL_SECONDS` | `60` | Metric persistence interval, in seconds |
| `CITADEL_AUTOMATIONS_ENABLED` | `true` | Enables Automation Action execution |
| `CITADEL_AUTOMATIONS_MAX_PARALLEL_RUNS` | `4` | Maximum concurrent Automation Action runs |
| `CITADEL_AUTOMATIONS_DEFAULT_TIMEOUT_SECONDS` | `300` | Default Action timeout |
| `CITADEL_AUTOMATIONS_MAX_TIMEOUT_SECONDS` | `1800` | Maximum Action timeout |
| `CITADEL_LOG_FORMAT` | `Text` | Core log format: `Text` or `Json` |

These settings do not override resource permissions, enabled states, or license
requirements. Resource schedules are configured on the resource itself.

For first-run password-file bootstrap, use the complete
[unattended setup procedure](/docs/getting-started/first-run-setup#unattended-setup).
For common configuration changes, see
[Docker Compose configuration](/docs/getting-started/configuration).

## HTTP listeners and runtime limits

Host-published ports above are separate from the container listeners. The supplied
Compose packages use the listen-port settings for container port targets and the
health check reads the same HTTP port. Bare binaries have no static-root default;
the packaged image sets `CITADEL_STATIC_ROOT=/app/wwwroot` and accepts an override.

| Setting | Default / units |
| --- | --- |
| `CITADEL_HTTP_LISTEN_PORT` / `CITADEL_EDGE_GRPC_LISTEN_PORT` | `8000` / `8001` |
| `CITADEL_HTTP_CORS_ORIGIN_<n>` | No origins; indexed list ordered numerically, sparse indices allowed; blank entries rejected |
| `CITADEL_HTTP_FORWARDED_LIMIT` | `1` trusted hop |
| `CITADEL_HTTP_BODY_LIMIT_BYTES` | `2097152` bytes |
| `CITADEL_HTTP_REQUESTS_PER_MINUTE` | `600` |
| `CITADEL_DATABASE_MAX_CONNECTIONS` | `5` |
| `CITADEL_DOCKER_SOCKET` | `/var/run/docker.sock` inside Core |
| `CITADEL_DOCKER_TIMEOUT_SECONDS` | `10` seconds |
| `CITADEL_STATIC_ROOT` | Optional frontend directory |
| `CITADEL_SHUTDOWN_TIMEOUT_SECONDS` | `10` seconds |
| `CITADEL_LOG_COLOR_ENABLED` | Terminal detection; JSON always omits ANSI color |
| `CITADEL_STATS_BATCH_SIZE` | `500` |
| `CITADEL_EVENT_QUEUE_CAPACITY` | `256` |
| `CITADEL_SWARM_RECONCILIATION_INTERVAL_SECONDS` | `1800` seconds |
| `CITADEL_RETENTION_INTERVAL_SECONDS` | `900` seconds |
| `CITADEL_REALTIME_ENABLED` | `true`; disabled realtime skips its other settings |
| `CITADEL_REALTIME_QUEUE_CAPACITY` / `CITADEL_REALTIME_MAX_CONNECTIONS` | `64` / `8` |
| `CITADEL_REALTIME_SUBSCRIBE_TIMEOUT_SECONDS` / `CITADEL_REALTIME_SEND_TIMEOUT_SECONDS` | `5` / `2` seconds |
| `CITADEL_REALTIME_AUTH_RECHECK_SECONDS` | `30` seconds |
| `CITADEL_REALTIME_SNAPSHOT_LIMIT` | `1024` |

In the development overlay, `CITADEL_DEV_DOCKER_SOCKET` selects the host socket
mount source; Core and the entrypoint both use `/var/run/docker.sock` inside the
container. The launcher derives this source from its native `CITADEL_DOCKER_SOCKET`.

Carry existing JWT/encryption key bytes into the named settings when changing
configuration. Generated keys remain in `jwtsecret` and `secret-encryption-key`
under the same data root. Offline recovery never generates replacement keys.

## Core connections to Agents

| Setting | Default / units |
| --- | --- |
| `CITADEL_CORE_AGENT_ADDRESS` / `CITADEL_CORE_AGENT_PRIVATE_KEY_PATH` | Optional pair; configure both together |
| `CITADEL_CORE_AGENT_TIMEOUT_SECONDS` | Required positive seconds when that pair is set |
| `CITADEL_CORE_AGENT_ALLOW_INSECURE` | `true`; set `false` to require HTTPS |
| `CITADEL_CORE_AGENT_CA_CERTIFICATE_PATH` | Optional PEM trust bundle for Direct Agents |
| `CITADEL_NODE_AGENT_CA_CERTIFICATE_PATH` | Optional Core CA distributed to Swarm node agents |
| `CITADEL_EDGE_AGENT_IMAGE` | Optional full image override |
| `CITADEL_EDGE_AGENT_IMAGE_REPOSITORY` / `CITADEL_EDGE_AGENT_IMAGE_TAG` | `ghcr.io/citadel-p/citadel.agent` / current build version; used without the full-image override |
| `CITADEL_EDGE_AGENT_SUPPORTED_NODE_ARCHITECTURE_<n>` | `amd64`, `arm64`; indices 0–31, numeric order, sparse indices allowed; blank/unknown values rejected |
| `CITADEL_EDGE_AGENT_NODE_AGENT_BOOTSTRAP_MINUTES` / `CITADEL_EDGE_AGENT_NODE_AGENT_SETUP_MINUTES` | `10` / `5` minutes |
| `CITADEL_EDGE_AGENT_NODE_AGENT_REMOVAL_GRACE_MINUTES` | `10` minutes |
| `CITADEL_EDGE_AGENT_NODE_AGENT_LIMIT_NANO_CPUS` | `500000000` nanocpus |
| `CITADEL_EDGE_AGENT_NODE_AGENT_LIMIT_MEMORY_BYTES` / `CITADEL_EDGE_AGENT_NODE_AGENT_PIDS_LIMIT` | `536870912` bytes / `256` processes |

Direct Agent containers require `CITADEL_CORE_PUBLIC_KEY`, the base64 Ed25519 public
key emitted by Core setup. Edge mode does not read that Direct-only setting.
Agent-owned `CITADEL_AGENT_*` and Edge profile settings are unchanged; use the
[Direct](/docs/operations/agent) and [Edge](/docs/operations/edge-agent)
setup guides for their generated configuration.
