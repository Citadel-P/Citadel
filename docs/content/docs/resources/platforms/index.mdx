title: "Platforms"
description: "Choose a Docker platform type and connect it to Citadel."
---

A Platform is a Docker host or Swarm cluster that Citadel manages. It supplies
the runtime for your applications and access to Docker inventory, logs, and
monitoring. Adding a Platform connects to existing infrastructure.

## Choose a Platform type

| Type | What it connects to | Managed workloads |
| --- | --- | --- |
| [Docker Standalone](/docs/resources/platforms/docker-standalone) | One Docker engine | Deployments and Compose Stacks |
| [Docker Swarm](/docs/resources/platforms/docker-swarm) | An active manager in an existing Swarm cluster | Swarm Services and Swarm Stacks |

Citadel does not initialize or join a Swarm cluster. Connect to its manager
after creating the cluster.

## Choose a connector

| Connector | Use it when |
| --- | --- |
| Local | Docker runs on the Citadel host and its socket is mounted into Core |
| [Agent](/docs/operations/agent) | Core can reach an Agent running on the Docker host |
| [Edge Agent](/docs/operations/edge-agent) | The host needs to connect outbound to Core |

Use one Platform per Docker engine. Citadel supports one Local Platform per
installation. A Swarm Platform represents the cluster through its manager;
[node coverage](/docs/resources/platforms/docker-swarm#understand-cluster-node-coverage)
extends node-local operations to its other eligible Nodes.

## Connect and operate a Platform

Follow [Connect a Docker host](/docs/getting-started/first-platform) for the first
connection. Then use the page for your Platform type to configure and manage it.

- [Platform monitoring](/docs/operations/platform-monitoring) explains connection status, metrics, and alerts.
- [Access control](/docs/guides/access-control) explains who can view or manage the Platform.
- [Adopt existing workloads](/docs/guides/adopting-existing-workloads) brings eligible applications under Citadel management.
