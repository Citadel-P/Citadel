---
title: Dashboards
description: Open saved dashboards, manage their audience, and choose defaults.
---

Signed-in users can save private dashboards. Only the owner can open or edit a private dashboard. Administrators can also create instance-shared dashboards that all signed-in users can read. Team adds restricted dashboards and delegated editing through Dashboard permissions. Access to a dashboard does not grant access to the resources it references. Dashboard names are unique across the instance, regardless of letter case.

Citadel creates a shared **Overview** example as the initial instance home. Administrators can edit, rename, or delete it like any other shared dashboard.

To create a board, open **Configuration → Dashboards → Create dashboard**, enter a name, add an optional Markdown description, and choose a template. **Blank** starts empty. **Overview** shows fleet counts, resources that need attention, workload states and recent activity. **Infrastructure and capacity** offers CPU and memory charts when you select a platform. **Application** shows deployment state, items that need attention, recent activity, and side-by-side CPU and memory charts for selected resources. **Maintenance** pairs resource updates with completed backup activity. For administrators, it also shows upcoming schedules in a timeline and summarizes update status for Citadel Core and PostgreSQL.

**Resource state** groups one resource type by status. The donut shows the total and the share in each state. Select a status count to see the matching resources. In **Needs attention**, one resource can have both a problem and an update. Select **Updates** to see available updates even when failures fill the preview. Select a row to inspect its evidence. Select a target in **Watchlist** to pin it. Use **Add resource** for the next pin, up to eight. **Notes and links** supports the same Markdown formatting as resource descriptions. Select an alert or activity in a timeline to open its details on the dashboard. Charts and watchlists follow platforms, deployments, stacks and managed Swarm services. A deployment pin follows its replacement container after a redeploy. To count containers by status, choose **Resource state → Containers**. To inspect one container, open its **Stats** tab.

In a **Resource state** sheet, search by resource name, image, or readable platform name. Each row links to the resource and shows available details, such as a container’s published ports or a stack’s current release.

Saved tag filters match resources that carry all the selected tags. Backup activity follows the backup policy’s tags. Alerts and recent activity follow the tags of their owning resource and appear only when you can read both the event and the owner. Instance-wide events have no tagged owner. Changing a resource’s tags updates which past events appear on the dashboard.

To share a restricted board on Team, open the user or team in **Access**, choose **Grant Access**, and select **Dashboard**. Choose **Read** to let them open the board or **Write** to let them edit it. Save the override and the user or team form.

Open **Configuration → Dashboards** in the sidebar to browse saved boards. Select rows to use the bottom action bar. You can set one dashboard as home or delete several together if you have permission to delete each one. To confirm deletion, type the dashboard name for a row action or `Delete` for a selection in the action bar. On a shared or restricted board, administrators can choose **Sharing** and confirm the new audience. Restricting a board requires Team. Sharing a restricted board with everyone also makes its saved notes and links visible to every signed-in user. Existing user, team and role grants keep their assigned levels. Personal boards always stay private, including boards owned by administrators.

Select the dashboard name to switch between saved boards. **Duplicate** below the name opens a copy you can customize. Choose **Edit dashboard** to open the widget library. On an empty board, **Add widget** opens it directly. Select the title or description to edit it, or select a widget to change its settings. Use the back arrow beside **Widget settings** to return to the library. **Add widget** reopens the library if you close the panel. On wider canvases, drag a tile over the twelve-column grid. The highlighted cells show where it will land. Resize it using its corner, a layout preset, or the coordinates in **Widget settings**. The canvas previews edits as you make them. **Undo** and **Redo** let you revise the draft. Choose **Preview** to try it before saving. **Save changes** saves the whole board. If someone else saves first, you can save your draft as a private copy. A board supports 24 widgets, including up to eight metric charts.

Use the tag filter to change which resources appear. **Chart range** sets the time window for metric charts. Widgets update automatically while the dashboard is open, including when you switch browser tabs. Change the tag filter or chart range in the editor to save it as the dashboard default. A pinned chart keeps its selected resource when you change filters. If the resource falls outside the filter or you lose access, the chart shows that state.

Metric charts use the selected resource’s statistics and support the same history windows, from 15 minutes to seven days. On larger CPU and platform memory charts, **Range** shows the lowest and highest displayed samples. In widget settings, you can pick a chart color or use the suggested color for that metric. Choose **Line**, **Area**, or **Gradient** in widget settings. Workload memory charts offer **Breakdown** and **Working set** when measurements are available. When a stack has several services, choose one in the chart. For stacks with more than eight current or recorded service names, use **Full statistics**. Upcoming schedules and instance updates require administrator access.

**Home** in the sidebar opens your personal default dashboard. If you haven’t chosen one, it opens the instance default if you can read it. If neither is available, Home prompts you to choose a dashboard. The **Home** column in the dashboard list marks the saved dashboard that opens for you. Opening a dashboard or saving a copy leaves your home preference unchanged.

On a saved dashboard, choose **Set as home** to open it whenever you visit Home. Administrators can also set a shared or restricted dashboard as the **Instance default**. To clear a choice, open **Dashboards → Reset home**. Resetting your own home restores the instance default. Resetting the instance default clears it.

In **Activities**, filter by **Dashboard** to see who created, edited, shared, or deleted a board. Open a creation or deletion event to view the saved configuration at that time, or an edit event to compare versions. Configuration snapshots omit description text, note contents, and note links. Events without a snapshot show a summary. Personal dashboard history is visible only to its owner. Shared dashboard history follows the board’s current audience. After deletion, its history is available to the private owner or, for a shared board, to administrators. Instance home changes appear under **Instance**.
